# Surlife M1.10 — Shared-Response Cognition in Non-Additive TaskPacks

**Opt-in:** `surlife --m110`. This milestone connects the M1.8
counterfactual response-bank method to the M1.9 versioned **coverage**
and **synergy** tasks. No existing M0–M1.9 experiment formats are changed.

## Scientific purpose

We want a meaningful comparison of LLM consultation against good cheap
classical strategies, not merely against a deliberately weak ratio-Greedy
solver. A single bank of sampled model responses removes the otherwise
uncontrolled variance from using different model answers for competing
cognition schedules.

The new cheap fallback is **marginal-gain Greedy** rather than the
original singleton-ratio Greedy. The experiment also measures beam search
and an unpriced exhaustive oracle, with per-family scores and final energy.
Never claim an LLM advantage from raw task scores alone.

## What's actually implemented

The run constructs deterministic M1.9 TaskPacks (the existing
`m19-v1` scoring rules), and obtains **one model response per task**,
subject to a strict provider cap, timeout and 429 circuit breaker.

The separate prompt adapter describes the ACTUAL task rule:

- **Coverage:** Only unique weighted features count. Overlap cannot earn
  duplicate points. Each item's listed reward is its *standalone* value.
- **Synergy:** Select items within budget; pair bonuses count **only** if
  both items are chosen.

The prompt includes the visible task, seeded weather, tick and a
**standardized starting energy of 30**. It does **not** include the
oracle solution, precomputed Greedy/marginal/beam masks, future puzzles
or the opponent's private information.

The model replies with a strict JSON integer subset bitmask. The trusted
referee settles that selection without correction: an invalid mask inside
the allowed bit range is a visibly invalid paid action. No model-produced
code is executed.

The saved bank is replayed fully offline across:

| Arm | Action |
|---|---|
| Greedy | Old unpriced singleton ratio-Greedy |
| Marginal | New unpriced marginal gain per cost |
| Beam | New unpriced finite-width beam search |
| Oracle | Unpriced exhaustive optimum diagnostic |
| Never | Always choose Marginal, pay nothing |
| Always | Pay for every available bank response up to virtual cap |
| Selective | Pay at every third tick when energy permits |
| Adaptive-fresh | M1.6-v2 policy decides whether to pay |

If an arm **doesn't consult**, it takes the marginal-gain solution.
A consultation costs one virtual energy regardless of provider tokens,
and a failed attempted consultation costs energy but **does not** teach
the policy that reasoning is bad. A 429 disables *later bank sampling*.
The original M0-v2 upkeep/duel/energy ledger still determines outcomes.

The `--m110-virtual-cap` applies to EACH simulated strategy. Real
provider requests are a separate one-time cost during bank collection.
A stored bank can be re-evaluated at several virtual caps without
credentials or additional provider requests.

## Try it offline (Fish)

Update your repository and install test dependencies:

```fish
cd ~/Documents/GitHub/surlife
git switch main
git pull --ff-only
python -m pip install -e '.[test]'
pytest -q tests/test_m110.py
```

Then perform a **free, fake-provider** run:

```fish
surlife --m110 --provider fake --a llm --b greedy \
  --seed 17 --benchmark-cases 4 --benchmark-items 9 \
  --m110-pack mixed --max-requests 4 \
  --m110-virtual-cap 4 \
  --benchmark-out out/m110-fake17.json

surlife --verify-m110-file out/m110-fake17.json
```

The fake provider picks the original ratio-Greedy solution. It is a
protocol and accounting check, **not a cognition benchmark**.

To try a different virtual budget with EXACTLY the same saved answers:

```fish
surlife --m110 --provider fake --a llm --b greedy \
  --seed 17 --benchmark-cases 4 --benchmark-items 9 \
  --m110-pack mixed --max-requests 4 \
  --m110-virtual-cap 1 \
  --m110-bank-in out/m110-fake17.json \
  --benchmark-out out/m110-fake17-cap1.json

surlife --verify-m110-file out/m110-fake17-cap1.json
```

The bank is replay-verified *before* reuse and must match the same
seed, taskpack, case count, item count, scorer version, prompt version,
provider, requested model, reasoning mode and output-token limit.
**Do not attempt to load an old M1.8 knapsack bank:** it is a
different world and a different prompt/scorer protocol.

## Later: bounded live Gemini sampling

Only run this when your Gemini account's quota and billing are working:

```fish
surlife --m110 --provider google --a llm --b greedy \
  --seed 17 --benchmark-cases 4 --benchmark-items 9 \
  --m110-pack mixed --max-requests 4 \
  --m110-virtual-cap 4 \
  --max-output-tokens 4096 --reasoning off \
  --google-timeout-seconds 45 \
  --benchmark-out out/m110-gemini17.json

surlife --verify-m110-file out/m110-gemini17.json
```

This authorizes **at most four actual model requests**, made once when
building the bank. Four is not the number of simulated calls across
all arms. Never confuse virtual energy with actual token costs.
Hosted sampling is limited to 12 cases, and automatic SDK retries are
disabled by the existing Gemini adapter.

`--m110-bank-in` enables zero-request rescoring of a previously saved
and verified Gemini bank, even if Gemini credentials are unavailable
at rescore time. Pass the SAME model/generation settings and a new
output filename.

## Evidence, integrity and caveats

Each report embeds full task observations, transactions, response bank,
per-tick policy decisions, learned feedback, per-family metrics and
SHA-256 content digest. The verifier regenerates the seeded tasks and
all trusted policy/referee decisions. A content digest is **not** an
authentication signature; a malicious author who can edit and fully
recompute every field could create self-consistent fabricated evidence.

**Old M1.7 policy snapshots are not imported into M1.10.** Those states
learned from one-tick energy gain relative to ratio-Greedy on additive
knapsack. Their contexts and reward meaning are not calibrated for
the stronger marginal fallback on coverage/synergy TaskPacks.
M1.10 starts with a fresh policy each run. Later cross-generation
inheritance should use TaskPack-specific training and held-out
promotion rules rather than mixing incomparable feedback.

This is still a series of deterministic puzzles, not a persistent
ecosystem. Stronger TaskPacks increase difficulty, but an exact
classical oracle remains available and unpriced; hence neither
model superiority nor open-ended evolution has been demonstrated.

## Next gate

Before advancing to a persistent M2 environment, require multiple
independent healthy response banks from the **same pinned model**,
held-out seeds, adequate token budgets, zero hidden solution leakage,
and measured positive **net virtual-energy value versus marginal
and beam**. Evaluate persistent resource decisions separately from
single-tick puzzle competence.
