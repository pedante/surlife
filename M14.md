# Surlife M1.4 — headroom-calibrated survival benchmark

**Opt-in stage:** `--m14`. This is a *controlled experiment*, not yet an
evolving life simulation. It does not modify M0–M1.3 referee rules or
historical SQLite journal replay. It uses a **separate benchmark JSON
report** with offline deterministic replay.

## Why

In a real M1.3 test on seed 17, the free OpenRouter organism submitted four
legal decisions but scored 82/114 on the tasks where it was consulted.
Greedy obtained 114/114 on those same tasks and 270/273 across the 12-tick
world. The LLM therefore had **no possible extra task reward** on any of its
four consultation decisions, while it still spent virtual energy on them.

M1.4 creates harder, versioned knapsack worlds (8–14 items) where Greedy
does not solve everything optimally. Default `mixed` uses half deliberately
constructed ratio-Greedy traps and half ordinary seeded random tasks.
Every trap has a verifiable positive Greedy-to-optimal gap. Disclose this
construction: it is a benchmark of strategy headroom, **not a realistic
random-world distribution**.

## Install and run

```fish
cd ~/Documents/GitHub/surlife
git fetch origin
git switch --track origin/implementation/m14-headroom-benchmark-20261012
python -m pip install -e '.[test]'
pytest -q
```

**Calibrate the tasks first, without any model or provider key:**

```fish
surlife --m14 --seed 17 \
  --a greedy --b greedy \
  --benchmark-cases 12 \
  --benchmark-items 12 \
  --benchmark-profile mixed \
  --benchmark-out out/m14-calibration.json
```

Three task profiles are available:
- `mixed`: alternating trap and random tasks (default)
- `trap`: all deliberately engineered for a Greedy gap
- `random`: seeded random cost/value combinations

The report compares three reference arms: **Greedy versus Greedy**, a
**cheap dynamic-programming solver (DP)** versus Greedy, and an **exact
exponential oracle** versus Greedy. Both algorithmic baselines are
unpriced under the current virtual-energy rules, but require real CPU
work. The oracle is a diagnostic upper bound, not free cognition.
DP runs in O(items × integer capacity) and solves these knapsack
instances optimally without model requests: an LLM beating Greedy
alone does NOT show that model-based intelligence adds value.

**Offline fake-provider comparison**:

```fish
surlife --m14 --seed 17 \
  --a llm --b greedy --provider fake \
  --cognition selective --max-requests 8 \
  --benchmark-cases 12 --benchmark-items 12 \
  --benchmark-profile mixed \
  --benchmark-out out/m14-fake.json
```

The fake model is deterministic and expected to approximate Greedy, not
learn. This tests complete energy accounting without a real provider key.

**Live free-model pilot, capped at one request**:

```fish
surlife --check-model
surlife --m14 --seed 17 \
  --a llm --b greedy --provider openrouter \
  --cognition always --max-requests 1 \
  --benchmark-cases 2 --benchmark-items 12 \
  --benchmark-profile mixed --reasoning off \
  --benchmark-out out/m14-live-pilot.json
```

The benchmark uses a new raw **8–14-bit mask JSON schema**; a
provider that supports M1.3's smaller legal-menu schema might still reject
this new schema. Check `provider_failures` before interpreting results.

After a successful one-request pilot, compare across several seeds:

```fish
surlife --m14 --seed 17 \
  --a llm --b greedy --provider openrouter \
  --cognition selective --max-requests 8 \
  --benchmark-cases 12 --benchmark-items 12 \
  --benchmark-profile mixed --reasoning off \
  --benchmark-out out/m14-live-seed17.json
```

Each request costs one unit of virtual cognition energy, irrespective of
tokens used. `--cognition never` disables external calls even with
`--a llm`, and must match the Greedy energy baseline.
`--cognition selective` is a **fixed, host-owned schedule** (every third
tick when affordable) and must not be mistaken for learned metacognition.

## Independently verify saved benchmark worlds

```fish
surlife --verify-benchmark-file out/m14-live-seed17.json
```

The report contains the generated tasks, full settled moves and transfers,
sanitized provider status/usage (no raw completions or API keys), summary,
and SHA-256 content digest. The verifier regenerates every task and
replays every move through the actual M0-v2 referee with the injected
task stream. It checks ledgers, energy, score, baseline actions and digest.
**This is consistency checking, not tamper-proof authentication**.

Do not use `surlife --replay RUN` on benchmark JSON files: that older
command is only for historical SQLite M0–M1.3 journals.

## Interpreting survival advantage

Report fields under `summary.headroom`:
- `greedy_total` and `oracle_total`: how much additional objective reward
  *could* theoretically be earned over Greedy
- `positive_gap_cases`: puzzles where Greedy does not reach the optimum
- `relative_headroom`: normalized gap over all tasks

Under `summary.arms`, compare the **LLM** arm with **Greedy**:
- `task_score_sum`, `legal`, `invalid`, `optimal`, and `model_actions`
  measure decision effectiveness
- `consultations`, `reported_tokens`, and `provider_failures`
  measure cognition cost and provider reliability
- `energy`, `alive` and `energy_delta_vs_no_inference`
  measure ecological outcomes of strategy differences, taking upkeep,
  rewards and duel transfers into account
- The **DP** arm is a much cheaper classical exact solver than brute-force
  enumeration; neither DP nor the **oracle** arm is priced by the current
  virtual cognition model. Do not interpret either as physically free.

Traps are designed against Greedy. The included **pure-Python dynamic
programming** policy already solves them exactly. Before declaring an
LLM useful, compare real wall-clock resources, price classical CPU in
the virtual ecology if appropriate, and investigate richer task families
where semantics or learning can add something to optimization.

## Safety, scientific scope and limits

- ≤14 items and ≤48 tasks prevent explosive oracle enumeration.
- No list of all legal masks is sent to the LLM: it proposes a compact
  integer mask. The referee independently checks capacity. A bad action is
  **not silently fixed**.
- A model can emit invalid masks, run out of budget, or return a provider
  error. Failed provider consultations still cost energy; trusted Greedy
  fallback is labeled.
- OpenRouter models must pass the free-tier catalog check, and the
  benchmark refuses random `openrouter/free` routing for comparative runs.
  A real run can still experience provider drift or model changes.
- Offline fake tests do **not** demonstrate intelligence or learning.
  At least repeated independent seeds, a cheap algorithmic competition,
  and untrained-vs-adapted organism comparisons are needed next.
- This stage does not execute model-generated code, grant tools, or
  give organisms host/network privileges.
