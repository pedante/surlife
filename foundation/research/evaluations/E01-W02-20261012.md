# E01-W02 — PettingZoo as a Surlife arena interoperability layer

**Date:** 2026-10-12  
**Status:** `smoke_pass` for real PettingZoo 1.27.0 API and strict native ledger parity; **research decision: adapt as OPTIONAL interoperability layer, do NOT adopt as Surlife core referee**. The adapter remains in PR #29 awaiting explicit maintainer acceptance; third-party runtime adoption is not implicitly authorized.  
**Candidate:** [Farama PettingZoo](https://github.com/Farama-Foundation/PettingZoo) W02.  
**Comparison:** Surlife stdlib native `NativeTaskArena` (B0) versus real PettingZoo `ParallelEnv` bridge around that exact referee (B2).  
**Research issue:** [#28](https://github.com/pedante/surlife/issues/28).

- Core dependencies declared at release: `numpy>=1.21`, `gymnasium>=1.0`, `typing-extensions>=4.4`. Do **not** install the `classic`, `atari`, `sisl` or `all` extras for this experiment. They substantially enlarge the dependency/asset surface.

## Integration actually attempted

- **Optional dependency only:** `pip install -e '.[pettingzoo,test]'`. Surlife's base package retains no third-party runtime dependency.
- **New adapter:** `src/surlife/pettingzoo_bridge.py`, implementing `SurlifeParallelEnv` as a genuine `ParallelEnv`. It uses the established `NativeTaskArena` unchanged as **sole** score, prize, energy, escrow, mint/burn, death and seeded task authority.
- **Actions:** `spaces.Discrete(33)` encodes 0..31 objective five-item masks plus 32 for wait; malformed booleans, floats, missing or unknown IDs reject before referee mutation. No shell, browsing, arbitrary executable code, external provider or access to secrets.
- **Observations:** Gymnasium `spaces.Dict` with 5×2 task costs/rewards, capacity, encoded public weather, own energy and tick; no rival balance or next seeded task. Agent terminations follow native death; truncation ends bounded episodes. `rewards` reflect **net virtual energy change** from native ledger, rather than a second independent scoring source. `infos` contain only own outcomes.
- **Parity checks:** Upstream `parallel_api_test`; 2/3/4/8/16 agents, varied seeds and duel/work variants; compare complete referee record and ledger after matching actions, survival, reset determinism and invalid action preflight. Full normal Surlife tests still run separately.
- **Benchmark:** `python -m surlife.pettingzoo_benchmark --repeats 9 --ticks 12`: compare wall-clock milliseconds per tick for native referee versus the PettingZoo API, with identical seed and precomputed organism decisions and full ledger parity each run. Host/software/dependency versions printed. These short timing samples are *indicative*, not a scalable performance proof.

## Hypotheses to test / decision rubric

- **B0:** Surlife native reference is dependency-free, objective and already replayable for 2–128 agents.
- **B1:** PettingZoo used directly cannot substitute for Surlife economy, spending, genetics and referee. It supplies a multi-agent *interface*, not the application.
- **B2:** Thin optional export bridge can make Surlife usable by existing PettingZoo-compatible tools and standard compliance checkers, without replacing our core.
- **B3:** Borrow schema/test principles without a runtime dependency if B2 fails conformance, parity, maintenance or portability.

## Negative findings and decision

1. **PettingZoo is not an arena engine replacement**: it standardizes interfaces but supplies neither mutation selection nor virtual-energy conservation, winner stakes, LLM calls or hermetic replay for arbitrary games.
2. **It does not make Surlife faster or simpler internally**: tested wrapper overhead of ~1.35–1.62× on these short tasks, plus additional dependencies and adapter code. B0 remains best for the minimal evolving-program experiment.
3. **It meaningfully enables optional external tooling**: compatibility with existing PettingZoo Parallel API utilities/test harnesses and a future RL baseline integration. **This is the reuse we tested**, not running arbitrary PettingZoo environments inside Surlife.
4. **Important early failures were found and fixed:** Gymnasium sampled `np.int64` actions which a strict Python-int-only adapter rejected. A separate optional-test collection bug imported NumPy before its skip guard, breaking stdlib-only CI; fixed. The final safety test checks that completed agents are not shown a future hidden task.
5. **No automatic adoption of external simulation authority**: an inbound PettingZoo game would need its own Surlife-owned trusted scoring/energy admission and reproduction tests. External env code can be untrusted; do not run it with host model credentials or normal filesystem privileges.

**Decision: ADAPT (optional PettingZoo boundary only); RETAIN native population referee and basic dependency-free install.** Keep #29 open until the owner explicitly approves the new extra as an opt-in supported integration. Otherwise the evaluation report still documents why replacing the Surlife core is not beneficial. No PettingZoo package imported into the default simulation. Future inverse environment integration is a distinct E01 experiment requiring legal and security gates.
