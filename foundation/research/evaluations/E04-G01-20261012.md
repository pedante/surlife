# E04-G01 — mini-SWE-agent as a Surlife organism core

**Date:** 2026-10-12.  
**Research status:** runtime evaluation proposed; real-package CI pending. This report is an evidence record, not adoption authorization.  
**Component under evaluation:** genuine upstream `minisweagent.agents.default.DefaultAgent` in a strict, data-only Surlife boundary.  
**Comparison:** `BuiltinOrganism` and deterministic `NativeTaskArena` versus `DefaultAgent` with a scripted fake model and **non-executing** `BoundedActionSink`.

- **MIT license**, copyright 2025 Kilian A. Lieret and Carlos E. Jimenez. Source only imported from optional installed wheel; no upstream implementation copied.
- Supports **Python >=3.10**. Package metadata declares 15 broad dependencies including `litellm`, `openai`, `datasets`, `pydantic`, `jinja2`, `requests`, `tenacity`, `textual`, `rich`, `prompt_toolkit`, `typer`, `python-dotenv`, `platformdirs`, `pyyaml`. This is much heavier than Surlife's stdlib-only core.
- **Untrusted execution by default:** `LocalEnvironment.execute()` calls shell processes using an environment containing host variables. The default `DefaultAgent.step()` calls `execute_actions(query())`, which delegates action dictionaries to `env.execute`. Never pass the host's local, Docker or other mini-SWE execution environment into a creature.
- **Import-time configuration side effects:** upstream `minisweagent.__init__` creates a global configuration directory and loads a dotenv file. The real-package tests isolate `MSWEA_GLOBAL_CONFIG_DIR`; the module is not imported from Surlife's default path.
- **Limits are not a host authorization boundary:** `DefaultAgent.query()` checks `step_limit`, `cost_limit` and wall-time, but assumes its configured Model and Environment. The LiteLLM adapter has retries, its own global statistics and dollar-cost estimates. These do not replace Surlife's actual request/token admission and charges.

## What this evaluation actually implements

- `src/surlife/mini_swe_bridge.py` is **opt-in research code only**; it imports `DefaultAgent` lazily.
- `MiniSWEOrganism` owns one real upstream `DefaultAgent`, independent per-organism model/call counter, limited chat history and recent own outcome buffer. It implements `decide(observation, rng)` and `feedback(own_result)`.
- `BoundedActionSink.execute` accepts only exact `{"mask": int | null}`, 0..31, once per step, and **never spawns a shell, makes a request, mutates the referee or runs generated Python**.
- `ScriptedNoProviderModel` feeds the same existing Surlife cheap policies through mini-SWE's *actual* `query -> execute_actions -> feedback` flow. It produces no genuine LLM reasoning, tokens or provider calls.
- Surlife's `NativeTaskArena` remains the only virtual-energy authority; the comparator explicitly charges one simulated cognition unit per consulted organism per tick.
- The evaluation does not add mini-SWE to Surlife's base package or CLI and does not change existing `population-v1`, `m21-v1`, or `m21c-v1` reports.
- The CI installs a genuine pinned upstream package **with `--no-deps`**, plus just the 5 known necessary core runtime libraries (Pydantic, Jinja2, Rich, python-dotenv, platformdirs). This specifically evaluates the smallest useful upstream component, **not the full default model/tool stack**. A future production candidate must separately resolve/review all dependencies.
- Test scope: 2/3/8 organisms, 3 fixed seeds, matched per-agent actions and complete referee state, deterministic random strategies, separate memories, host request cap, denial of shell/extra fields, no code execution, no rival/credential fields, and no-provider economics. A small CPU decision-loop benchmark contrasts both without paying for model inference.

## Options to compare

- **B0 Native:** ~a few direct Python calls per observation, stdlib-only core, straightforward host-budget enforcement. Does not supply a multi-step code editing assistant or upstream SWE tools.
- **B1 Upstream as-is:** **FAIL trust/isolation** for creatures, due to intended command execution and model SDK credential scope; cannot adopt unchanged as a Surlife organism.
- **B2 Actual DefaultAgent with custom inert Model + Environment:** may pass action safety and isolation for a *scripted fixture*, but duplicates task-scoped action selection and incurs dependencies/runtime overhead, and upstream startup and cost accounting need extra controls.
- **B3 Study/extract patterns:** borrow simple query/action/feedback protocol, independent bounded memory and evaluation archive; keep Surlife host-owned gateway and strict action/referee contracts.

**Candidate recommendation before empirical evidence:** do not install mini-SWE-agent as the required Surlife organism kernel. It has useful conventions for future **isolated code mutation workers** once the M2.2 sandbox is independently tested, but the heavyweight software-engineering shell/tool assumptions conflict with lightweight many-agent survival and scarce consultations. Adopt B2 *only* if the experiments show a concrete advantage over our small native loop under all safety and accounting requirements.
