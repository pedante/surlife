# E04-G01 — mini-SWE-agent as a Surlife organism core

**Date:** 2026-10-12.  
**Research status:** `smoke_pass` on real pinned DefaultAgent, decision **STUDY / DO NOT ADOPT as organism core**. This is an evaluation record, not third-party runtime adoption authorization.  
**Component under evaluation:** genuine upstream `minisweagent.agents.default.DefaultAgent` in a strict, data-only Surlife boundary.  
**Comparison:** `BuiltinOrganism` and deterministic `NativeTaskArena` versus `DefaultAgent` with a scripted fake model and **non-executing** `BoundedActionSink`.

## What this evaluation actually implements

- `src/surlife/mini_swe_bridge.py` is **opt-in research code only**; it imports `DefaultAgent` lazily.
- `MiniSWEOrganism` owns one real upstream `DefaultAgent`, independent per-organism model/call counter, limited chat history and recent own outcome buffer. It implements `decide(observation, rng)` and `feedback(own_result)`.
- `BoundedActionSink.execute` accepts only exact `{"mask": int | null}`, 0..31, once per step, and **never spawns a shell, makes a request, mutates the referee or runs generated Python**.
- `ScriptedNoProviderModel` feeds the same existing Surlife cheap policies through mini-SWE's *actual* `query -> execute_actions -> feedback` flow. It produces no genuine LLM reasoning, tokens or provider calls.
- Surlife's `NativeTaskArena` remains the only virtual-energy authority; the comparator explicitly charges one simulated cognition unit per consulted organism per tick.
- The evaluation does not add mini-SWE to Surlife's base package or CLI and does not change existing `population-v1`, `m21-v1`, or `m21c-v1` reports.
- The CI installs a genuine pinned upstream package **with `--no-deps`**, plus just the 5 known necessary core runtime libraries (Pydantic, Jinja2, Rich, python-dotenv, platformdirs). This specifically evaluates the smallest useful upstream component, **not the full default model/tool stack**. A future production candidate must separately resolve/review all dependencies.
- Test scope: 2/3/8 organisms, 3 fixed seeds, matched per-agent actions and complete referee state, deterministic random strategies, separate memories, host request cap, denial of shell/extra fields, no code execution, no rival/credential fields, and no-provider economics. A small CPU decision-loop benchmark contrasts both without paying for model inference.

## Empirical integration and safety results

**Actual upstream package** `mini-swe-agent==2.4.6` was installed without its complete model/CLI dependency graph in isolated CI, plus its minimal executable core requirements (`pydantic`, `jinja2`, `rich`, `python-dotenv`, `platformdirs`). This uses upstream `DefaultAgent.step()` itself, **not** a copied reimplementation.

Evidence: [GitHub workflow E04-G01 run 38273703604](https://github.com/pedante/surlife/actions/runs/38273703604), with **16 E04 tests passing on both Python 3.10.22 and 3.13.16**. Package versions included mini-SWE-agent 2.4.6, Pydantic 2.14.1 and Jinja2 3.1.6 on both CI workers.

- **PASS — genuine workflow integration:** native `greedy`, `optimal`, `random`, `wait` outputs are routed through actual mini-SWE's query/action/feedback loop and match original `NativeTaskArena` decisions, results and virtual-energy ledger on 2, 3 and 8 players across seeds 0/17/101. Paired comparisons explicitly charge the same simulated cognition fees and record no provider tokens.
- **PASS — scoped identities/memory:** instances don't share messages, model state or scoped feedback; the host truncates per-agent chat histories to 8 entries. Upstream does not natively impose this bound.
- **PASS — hostile action refusal in the narrow fixture:** shell-like action dictionaries, arbitrary extra keys, source/prompt edits, boolean/float masks, out-of-range values and multiple actions fail in the inert sink, with no referee step or host command. No real code-execution sandbox has been tested or claimed.
- **PASS — request-count control in the narrow fixture:** upstream `step_limit` plus an independent adapter `max_calls` check stop further scripted queries. Its dollar-cost meter is neither used nor accepted as host authority.
- **PASS — economic negative control:** where the native cheap strategy already produces the identical result, charging each additional mini-SWE fake consultation reduces the organism's energy by the exact number of consultations. No adaptive improvement shown.
- **LIMITATION:** the tests inject a deterministic `ScriptedNoProviderModel`, not an actual LLM model gateway. Real provider token/currency reconciliation, partial failure, dynamic code mutation and hostile generated module sandbox are **not** covered.
- **LIMITATION:** `minisweagent.__init__` creates a configuration directory and calls `dotenv.load_dotenv` when imported. GitHub CI sets an isolated empty config path. Never import arbitrary organism code into this interpreter as a substitute for isolation.

## Quantified engineering trade-off

Scores use the repository's rubric, **0–5 by engineering judgement**, after checking applicability of the hard gates. Weights: safe integration 25%, deterministic replay 20%, reusable functionality 20%, request/cost control 15%, scientific utility 10%, maintenance/rights 10%.

| Dimension | Native B0 | B2 inert mini-SWE adapter | Rationale |
|---|---:|---:|---|
| Minimal safe integration (25%) | 5 | 2 | B2 requires adapting external defaults, overriding tools, isolated config and manual memory bounds |
| Replay/scoring (20%) | 5 | 5 | Both reproduce identical deterministic results with the existing referee |
| Reuse value (20%) | 4 | 2 | Model/action/feedback loop reusable, but Surlife already provides the needed constrained interface |
| Host cost control (15%) | 5 | 4 | B2 can be wrapped, but internal cost estimates are not trusted and full provider integration untested |
| Scientific utility (10%) | 3 | 3 | No demonstrated autonomous adaptation in either scripted fixture |
| Maintenance/license (10%) | 5 | 3 | MIT, but upstream large model/CLI dependencies and interface/version coordination |
| **Weighted score** | **92 / 100** | **62 / 100** | These are qualitative engineering scores, not agent performance scores |

**B1 directly adopted upstream** is *ineligible* under the trust and isolation gates regardless of any numerical score.

## Decision and next action

**STUDY / DO NOT ADOPT mini-SWE-agent as Surlife's default organism brain.** The actual DefaultAgent loop works behind our strict adapter, but contributes no additional capability in this bounded five-item decision task, costs 2.6–4.4× more CPU in the loop microbenchmarks and adds host/credential/config side-effect and dependency surfaces. Maintaining the adapter for every Surlife organism would be disproportionate until a more complex target task demonstrates clear reusability gains.

**Retain** the native host-owned inference/mutation/evaluation system, small organism `decide/feedback` contract, and ability to plug in a different brain. **Study** mini-SWE's concise loop and developer ergonomics for a *future sandboxed M2.2 code-mutation worker*, only once sandbox protections and tested authority boundaries exist. An optional agent integration may be reconsidered if code-repair trials show a real improvement in total held-out fitness **after** all real provider tokens, failures, time and virtual energy are accounted for.

Do not merge this research adapter as a production dependency by default. Keep #30 open for owner review, record findings in #28, and evaluate nanobot separately if meaningful. The user-approved strategic direction remains **evolution-first rather than an ecological world engine**.
