# Surlife M1.8 — Counterfactual Cognition Tournament

**Opt-in:** `surlife --m18`. No change to M0-v2 energy, duel,
upkeep or the existing M1.4 knapsack generator. M1.6/1.7 workflows remain
available with their historical command flags.

## Scientific question

M1.7's comparisons require independent LLM calls for a fresh and an
inherited policy. Stochastic provider responses can make one strategy
appear better even if the consultation schedule is worse. M1.8 removes
**this particular confound**: it asks the model about each selected task
exactly once, stores the bounded outcome in a common **response bank**,
then evaluates all cognition strategies using that SAME bank.

It is not a second hidden LLM and is not a new sophisticated agent.
The experimental organism still controls whether to spend virtual energy
on a result. Model-produced code is never run.

## Contract

1. **One sampling pass:** For each `--benchmark-cases N` task, construct a
   reference observation with the real seeded weather and task, but a
   **fixed 30-energy value**. The model never sees future tasks, oracle
   masks, precomputed Greedy masks, or another organism's private state.
   Neutral reference energy is necessary to keep the same sampled
   response usable by arms with different energy histories.
2. **One audited response per tick:** Either a structured mask and sanitized
   token usage; a charged provider failure; or an `unavailable` entry
   after a 429 circuit breaker. No raw provider answer or credential saved.
   The model cannot revise the bank after an arm has started.
3. **Many completely offline simulations:** Greedy, polynomial DP and
   unpriced exact oracle, plus **never**, **always**, **selective**
   (every third tick), and **adaptive-fresh** (M1.6-v2 policy). With a
   properly promoted M1.7-v2 snapshot, also **adaptive-inherited**.
   Every arm uses the identical stored response for tick `t`, but must
   decide whether to consult *before* learning the stored outcome.
4. **Same economic rules:** Each virtual consultation (including a sampled
   failure) costs one energy in the original referee. Model successes
   update the adaptive policy using its post-outcome matched one-tick
   Greedy counterfactual. Failures are charged but do not teach model
   quality; 429 disables further real bank sampling.
5. **Separate actual versus virtual spending:** `bank_sampling.provider_requests`
   counts REAL requests made while sampling; `arms.*.consultations`
   counts VIRTUAL fee-paying calls in a simulated organism. Those numbers
   are not interchangeable. Real request preflight requires at most
   12 bank cases, max-requests >= cases and a reviewed provider/model.
6. **Independent offline verifier:** Reconstruct tasks, bank validation,
   every strategy, energy transaction, cognition decision, learning
   update, all metrics, and the content digest. This detects
   inconsistent/tampered reports but is **not a cryptographic signature**.

The headroom here remains a narrow bounded-integer knapsack world.
Unpriced dynamic programming can still solve every task optimally. A
model beating ratio-Greedy is not evidence that LLM computation is
economically optimal versus DP. This milestone improves experimental
comparability, **not general intelligence**.

## Try offline in Fish (no model/API calls)

```fish
python -m pip install -e '.[test]'
pytest -q tests/test_m18.py

surlife --m18 --provider fake --a llm --b greedy \
  --seed 17 --benchmark-cases 4 --benchmark-items 12 \
  --max-requests 4 --m18-virtual-cap 4 \
  --benchmark-out out/m18-fake17.json

surlife --verify-m18-file out/m18-fake17.json
```

Expected with the fake provider: all sampled masks equal Greedy, so
the `never` arm ties the free Greedy control; `always` should be
worse by four virtual energy. Never interpret a cheaper fake
consultation schedule as a gain from reasoning.

## Rescore one bank without new requests

Change the *virtual* consultation budget while preserving exactly the
same prior sampled model outputs:

```fish
surlife --m18 --provider fake --a llm --b greedy \
  --seed 17 --benchmark-cases 4 --max-requests 4 \
  --m18-virtual-cap 1 \
  --m18-bank-in out/m18-fake17.json \
  --benchmark-out out/m18-fake17-cap1.json

surlife --verify-m18-file out/m18-fake17-cap1.json
```

This command does not open a gateway or make provider requests. Bank reuse
enforces the original seed, task configuration, model provider, reasoning
setting and output-token budget. If an M1.7-v2 snapshot was accepted,
`--policy-in PATH` adds an inherited adaptive comparison, with
provider/model/generation identity enforcement.

## Sampling real Gemini later (explicitly opted in)

Ensure Google quota/billing is configured. `--reasoning off` maps to the
model's LOWEST available thinking level, not true disabled thinking.

```fish
surlife --m18 --provider google --a llm --b greedy \
  --seed 17 --benchmark-cases 4 --max-requests 4 \
  --m18-virtual-cap 4 --google-timeout-seconds 45 \
  --max-output-tokens 4096 --reasoning off \
  --benchmark-out out/m18-google17.json

surlife --verify-m18-file out/m18-google17.json
```

The above permits a maximum of **four real Gemini consultations** in
the bank-building phase, with no retry by Surlife and the SDK automatic
retries disabled. If one returns 429, later samples are marked
unavailable; this is not evidence against the model's ability.
Use a *new filename* for each run. To rescore this real bank without
credentials/network, pass `--m18-bank-in out/m18-google17.json`
with the same `--provider google --max-output-tokens 4096` and a new
output filename.

## Next research milestone

Use this response-bank approach when adding new versioned **TaskPacks**
with language/constraints, delayed rewards or partially observable
state. A new task family must be deterministic, have an independently
audited scorer, avoid hidden-solution leakage, and include strong
cheap non-LLM controls. Do not add model-generated executable organism
code before a real isolation/security boundary exists.
