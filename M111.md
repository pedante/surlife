# Surlife M1.11 — Inherited Cognition for Coverage and Synergy

**Opt-in:** `surlife --m111` (offline only). M1.11 learns **when**
to consult a model on M1.9 TaskPacks and evaluates inherited experience on
**held-out M1.10 response banks**. It never calls Gemini, OpenRouter or a
local LLM. Real responses, if used, must have been sampled earlier by an
explicit `surlife --m110` run.

## Why M1.11?

M1.10 proved the real methodological problem: our fake model follows
singleton-ratio Greedy and therefore can be much worse than marginal-gain
Greedy and beam search, *even before charging the model consultation fee*.
The original adaptive policy can learn to use that fake provider less, but
energy saved relative to always consulting does not prove real cognitive value.

M1.11 adds **two independent cognition memories**, one for each TaskPack
family: `coverage` and `synergy`. Each family still has the M1.6
observable `routine` and `uncertain` buckets, with bounded numeric
`visits`, `trials`, and `gain` state.

These are four separate value-learning cells, not executable code or
natural-language reflection. The trusted policy decides whether to consult
*before* seeing the saved model answer. Only successful, actually used
answers update the learned value against **marginal-gain Greedy**.
Provider failures cost virtual energy but are not evidence that the model
reasoned badly.

## M1.11 workflow

1. Produce **one to four training** and **two to four held-out**
   independently verified M1.10 reports. Every bank uses the same
   provider, pinned model, reasoning/output budget, scorer, prompt,
   TaskPack, case count and item count. All training banks must be
   healthy. Duplicated seeds and matching task fingerprints across
   training/holdout are rejected.
2. Train a fresh family-specific cognition policy on each training
   bank, then combine only its bounded numeric state increments.
   Each learned action/energy transaction is re-simulated using the
   unchanged M0-v2 referee.
3. Re-evaluate fresh-vs-inherited cognition against the **same saved
   model answers** on each held-out bank, with the same per-organism
   consultation budget. Reference outcomes from no-inference marginal
   and unpriced beam search are also recorded.
4. **Promote** a data-only state snapshot only if inherited final energy
   never regresses against **either** fresh cognition or no-inference
   marginal on any held-out bank, and achieves strictly positive
   aggregate energy gain against **both**. Provider failures and an
   increase in invalid actions veto promotion.
5. Save the complete, independently replayable provenance: training
   and held-out bank reports, task fingerprints, policy traces,
   settlement ledgers, learned state, scoring and SHA-256 content hash.

Beam search remains a serious **unpriced diagnostic**, rather than a
hard promotion requirement: it can itself equal the exact oracle on the
small bounded TaskPacks. Requiring a paid model to outperform a free
optimal baseline would otherwise forbid any promotion. Any accepted
M1.11 snapshot still must not be described as proving superiority to
beam search or general intelligence.

This is a deterministic held-out heuristic gate, **not statistical
significance**. Bank outputs may be stochastic across independent live
samples, and the ability to edit/recompute a JSON content hash means
report hashes are not cryptographic signatures.

## Example: fully offline M1.11 fake-model research (Fish)

Update your source and create four independent M1.10 banks:

```fish
cd ~/Documents/GitHub/surlife
git switch main
git pull --ff-only
python -m pip install -e '.[test]'

for seed in 17 19 101 103
    surlife --m110 --provider fake --a llm --b greedy \
      --seed $seed --benchmark-cases 4 --benchmark-items 9 \
      --m110-pack mixed --max-requests 4 --m110-virtual-cap 4 \
      --benchmark-out out/m110-m111-$seed.json
end
```

These bank filenames must be NEW. If you already generated the same
files, use the existing reports instead of overwriting them.

Now inherit across seeds **17 and 19**, then compare against fresh
policies on held-out seeds **101 and 103**:

```fish
surlife --m111 --provider fake --a llm --b greedy \
  --m111-train-bank out/m110-m111-17.json \
  --m111-train-bank out/m110-m111-19.json \
  --m111-holdout-bank out/m110-m111-101.json \
  --m111-holdout-bank out/m110-m111-103.json \
  --m111-virtual-cap 4 \
  --benchmark-out out/m111-fake-evaluation.json \
  --m111-promote-policy-out out/m111-fake-policy.json

surlife --verify-m111-file out/m111-fake-evaluation.json
```

**Expected fake-provider result:** `accepted: false` with
`no_positive_gain_vs_marginal` among the rejection reasons. No
`out/m111-fake-policy.json` should be written. That rejection is a
research safeguard, not an execution error.

M1.11 does not require provider keys, make live requests, or charge
tokens. It can also consume separately sampled healthy **Gemini**
M1.10 reports later: pass `--provider google --model ...` and the
same generation settings (including `--max-output-tokens`) as the
saved banks. The actual request budget is fully controlled at the
preceding M1.10 bank-collection stage.

## Scientific scope and next steps

M1.11 produces a data-only promoted snapshot only after a conservative
held-out acceptance gate. It deliberately **does not load older M1.7
knapsack-trained snapshots**: their cognition feedback was calibrated
against a weaker ratio-Greedy fallback on different task semantics.

The first M1.11 version exports a promoted TaskPack-specific snapshot
for inspection and subsequent reviewed extensions. It does not yet
automatically import it into open-ended agent generations or modify
organism Python. A later milestone can add a bounded loader and
multi-generation evaluation with lineage validation.

For the more ambitious Surlife project, **persistent world consequences**
rather than additional one-off optimization puzzles should be the next
major M2 research direction. Keep the referee, model credentials and
real payments outside organism control.
