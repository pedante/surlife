# Surlife M1.9 — Deterministic Non-Additive TaskPacks

**Implemented as a separate, offline, opt-in benchmark**: `surlife --m19`.
It does not change the existing M0–M1.8 arena, historical JSON protocols,
Gemini provider, cognition policy, or model request ceilings.

## Why now?

All prior benchmark tasks are small **additive 0/1 knapsack** puzzles.
A cheap dynamic-programming solver is already exact in this world.
Adding a more expensive reasoning agent before distinguishing which tasks
actually benefit from extra reasoning would risk misleading conclusions.

M1.9 introduces new task rules first, independently benchmarks their
difficulty, and leaves LLM integration for a separately reviewed milestone.

## Two fully visible worlds

**Coverage**: Each item has a resource cost and covers 1–3 features.
Features have different positive weights. The organism selects a subset
within a capacity budget; it earns the total weight of **distinct** covered
features. Selecting two items that cover the same feature does not pay
twice. The old per-item greedy ratio uses each item's standalone coverage
as a heuristic and can double-count overlapping benefits.

**Synergy**: Each item has a resource cost and base value. Some publicly
listed item pairs grant an additional bonus **only when both are selected**.
The old ratio-Greedy ignores complementarity and may select attractive
single items instead of a valuable pair.

`--m19-pack coverage|synergy|mixed` selects either world, or alternates
them predictably by tick. All costs, weights, feature masks and pairwise
bonuses are in the public task observation. No private optimum or target
answer is placed in the task data.

The scorer is pure Python, fixed by the host; user/model data is never
interpreted as Python code. An independent reference scorer recomputes
the oracle from each possible mask (up to 2^14). Test cases compare the
two scorer implementations exhaustively for small tasks.

## Four meaningful reference policies

- **Greedy**: existing fixed ratio-of-singleton-reward/cost heuristic.
- **Marginal**: repeatedly chooses the highest *actual marginal* gain
  divided by cost; strong for many overlap tasks.
- **Beam**: bounded-width 48 prefix search with cost-aware ordering.
  It is a practical but *not guaranteed optimal* approximate solver.
- **Oracle**: unpriced exhaustive search, used only as a diagnostic.

All four compete against the same Greedy opponent, seeded task stream
and weather, and settle through the **original M0-v2 trusted energy
ledger**, including upkeep, prizes, duels and possible death.

**All computation is currently unpriced**. Scores and energy differences
are useful task-characterization measurements, not proof that an LLM is
better than a specialized classical solver.

## Run in Fish when convenient

```fish
cd ~/Documents/GitHub/surlife
git switch main
git pull --ff-only
python -m pip install -e '.[test]'

surlife --m19 --provider fake \
  --a greedy --b greedy \
  --seed 17 --benchmark-cases 8 --benchmark-items 10 \
  --m19-pack mixed \
  --benchmark-out out/m19-mixed-17.json

surlife --verify-m19-file out/m19-mixed-17.json
```

This uses **zero** Gemini/OpenRouter requests. The offline report contains
the full public scoring rules for every generated task, all actions, ledger
transfers, baseline outcomes and an independently replayable content hash.

The scorer's exact oracle is exponential and bounded to 14 items. Large
runs with 14 items may take noticeably longer than the old knapsack bench.
Start with 8–10 items and 4–8 cases.

## Gates for the next milestone

Before routing real model requests to these taskpacks, require:

1. Independent scorer/oracle agreement and deterministic replay across
   seeds and Python versions.
2. A positive measured gap between cheap Greedy and the best classical
   baselines on some held-out tasks, with honest results if none exists.
3. An independent *model prompt adapter* spelling out overlap/synergy
   rules without revealing oracle output or winner.
4. A versioned response-bank protocol keyed to taskpack, scoring version,
   seed, cases, model, and generation settings; no reuse across worlds.
5. Matched controls including the new marginal and beam baselines, not
   just ratio-Greedy. Keep strict caps on hosted requests and timeouts.

**M1.9 is world research infrastructure, not open-ended ALife.**
Evolution of organism prompts/code and interaction with a persistent
multi-agent ecosystem remain future tasks requiring separate security and
scientific evaluation.
