# Surlife M1 — bounded editable LLM souls with OpenRouter Free

**Experimental stage.** M1 is a small local harness, not a general autonomous agent, self-improving verified model or safe code-execution sandbox. Work is restricted to the referee's bitmask task API.

## Quick start in Fish (CachyOS / Arch)

From your Surlife repository after checking out the M1 branch:

```fish
source .venv/bin/activate.fish
python -m pip install -e '.[test]'
pytest -q
surlife --seed 7 --ticks 8 --a llm --b greedy --provider fake --max-requests 4
```

That last command uses a deterministic **fake provider**. It does not use OpenRouter or need a key; it tests souls, provider accounting and replay.

To run actual free inference, create your key at https://openrouter.ai/settings/keys and read it into your Fish environment **without pasting it into command history**:

```fish
read --silent --prompt-str 'OpenRouter API key: ' OPENROUTER_API_KEY
set -gx OPENROUTER_API_KEY $OPENROUTER_API_KEY
surlife --seed 7 --ticks 8 --a llm --b greedy --provider openrouter --model qwen/qwen3.8-27b:free --max-requests 4
```

Use `set -e OPENROUTER_API_KEY` to remove the Fish variable when finished. Never put the key in a soul, Git file or chat. **Live inference has not been exercised by the automated tests** and requires an actual account/API key.

The default is now the pinned, general-purpose `qwen/qwen3.8-27b:free` model. The optional `openrouter/free` route **randomly selects among available free models**, which previously selected a safety classifier instead of a puzzle-solving model. For scientific comparisons, keep a stable, currently available explicit `provider/model:free` slug (verify availability at https://openrouter.ai/collections/free-models). The gateway rejects model slugs not ending in `:free` unless exactly `openrouter/free`. There is no automatic paid fallback. Free tier quotas and providers' availability may change; check https://openrouter.ai/docs/api-reference/limits and your account limits.

## What an M1 organism actually owns

- **Soul:** separate versioned system-strategy text per actor, optionally loaded from `--soul-a path.txt` or `--soul-b path.txt`. A model may propose at most three compact strategy-note revisions, only after an objectively imperfect attempt. Proposals are appended for later ticks, **not** independently evaluated or known to improve fitness.
- **Memory:** up to eight recent task-result records per organism. Only four records enter a new prompt. No opponent private data is exposed.
- **Action:** one data-only JSON object (`{"mask": 9, "soul_update": "Compare combinations."}`), where bit `i` selects task item `i`. The trusted referee validates and scores it. No executable Python, shell, network tool or economic authority is attached to organism output.
- **Consultation:** one virtual-energy unit per admitted request, even if it errors. A host gateway applies `--max-requests` (default 6) and `--max-output-tokens` (default 512, maximum 1024). Calls are serialized; no automatic retries. If a call fails, budget is exhausted or energy is too low, a **trusted Greedy fallback** acts; its turns are distinguishable in journal metadata.
- **Provider metadata:** actual routed model and provider-reported input/output tokens (possibly missing), failure status and soul versions recorded per tick. The API key and raw response/prompt are not persisted. Replay reuses submitted actions, never resends a model request.
- **Persistence:** `out/souls/<run_id>/a.json` and/or `b.json` store data-only soul versions, notes and memory; `out/surlife.sqlite` holds the immutable round ledger. A crashed M1 session is **not resumable under the same run ID**; choose a new run ID. You **can carry a soul and its bounded memory into a later run** with `--inherit-soul-a` or `--inherit-soul-b` and a prior JSON snapshot. This continues organism lineage, not the unfinished world tick. Replay checks the world ledger, not faithful regeneration of prompt text or model outputs.

## Examples

```bash
# Both actors LLM-based, four paid-in-virtual-energy consultations maximum across them:
surlife --a llm --b llm --provider openrouter --max-requests 4 --ticks 12

# Continue A's prompt revisions and memory in a *new* experiment:
surlife --a llm --b greedy --provider fake --inherit-soul-a out/souls/YOUR_OLD_RUN_ID/a.json --ticks 8

# Pin a known zero-priced :free model to reduce routing confounds:
surlife --a llm --b greedy --provider openrouter --model qwen/qwen3.8-27b:free

# Replay needs no API key (replace ID with the one printed by your run):
surlife --replay YOUR_RUN_ID
```

Qwen3.8 27B is a documented free general-purpose model; free availability and quotas may change. By default, the other actor remains Optimal if `--b` is omitted; this example explicitly picks Greedy.

## Diagnose OpenRouter requests without exposing your key

If a live run reports similar scores to Greedy and `unknown_usage_requests` equals `model_requests`, **do not assume that the LLM actually played**. Model errors previously shared one opaque status. In the revised code, the JSON summary includes a `failure_reasons` counter, such as:

- `http_429`: rate-limited; consult OpenRouter limits, do not immediately retry repeatedly
- `http_401` / `http_403`: credentials or permissions may be wrong
- `provider_error_503` / `completion_error_502`: provider error even if HTTP status was 200
- `invalid_json` / `missing_mask` / `invalid_mask`: model replied, but the action schema was unusable
- `unsuitable_model`: the served model is a known non-chat model (moderation, reranking, embedding)
- `empty_content` / `completion_truncated`: no action text or output exhausted the completion-token limit
- `network_failure` / `invalid_response`: communication or response shape error

The CLI now defaults to **512 max completion tokens** (up to 1024 configurable) because reasoning models may consume completion tokens before emitting action JSON. No automatic retries are performed. The parser also accepts a well-formed JSON object inside a Markdown code fence or brief preamble, still validating `mask` as a bounded integer/null. Failures take the scripted Greedy fallback; attempted calls are still charged virtual energy, regardless of whether token usage is available.

Try **one request first** on a fresh run ID. Use the **pinned** Qwen model, not the random router:

```fish
surlife --seed 7 --ticks 2 --a llm --b greedy --provider openrouter --model qwen/qwen3.8-27b:free --max-requests 1 --max-output-tokens 512
```

If it succeeds, the summary's `routed_models` should list a model name from the provider, `failure_reasons` should be empty, and a status `ok` will appear in the journal. Token usage may still be unavailable, and a successful answer is not proof of learning. **No API key or raw model text is saved in the event log.**

To inspect only sanitized diagnostics from a run, replace `RUN_ID` below:

```fish
python -c 'import sqlite3,json; c=sqlite3.connect("out/surlife.sqlite"); rows=c.execute("SELECT tick,payload FROM rounds WHERE run_id=? ORDER BY tick",("RUN_ID",)); [print("tick",t,json.loads(p).get("model_calls",{}).get("a",{}).get("status"),json.loads(p).get("model_calls",{}).get("a",{}).get("failure_reason")) for t,p in rows]'
```

Existing runs created before this diagnostic update will still have the old generic status; their specific failures cannot be recovered retroactively.


## Reasoning tokens and the free router

An actual pilot with `openrouter/free` returned `completion_truncated` after the 512-token completion allowance was consumed. This was **not a valid LLM decision**; the referee used Greedy fallback. OpenRouter documents that some reasoning models spend most or all completion tokens internally, leaving an empty answer.

**New default:** Surlife asks OpenRouter to disable reasoning (`--reasoning off` sends `{"reasoning":{"enabled":false}}`), so the small JSON move has a better chance of arriving within the completion budget. This is a **request**, not a guarantee: an underlying model may ignore it or require reasoning. Choose `--reasoning low` for models that benefit from limited reasoning or `--reasoning auto` to use the provider's defaults. The selected setting is written in the run manifest and CLI output.

Use at most **one free request** to test after upgrading:

```fish
git pull --ff-only
pytest -q
surlife --seed 7 --ticks 2 --a llm --b greedy --provider openrouter --model qwen/qwen3.8-27b:free --max-requests 1 --max-output-tokens 512 --reasoning off
```

If `failure_reasons` still contains `completion_truncated`, try `--max-output-tokens 1024` on one fresh run and consider a pinned current non-reasoning `:free` model. For scientific comparisons, pin the model: `openrouter/free` intentionally chooses underlying models dynamically.

The gateway also now keeps provider-supplied token counts and model IDs on a truncated response where available. Missing token accounting remains explicitly reported; no model key, prompt, or raw provider text is stored. **Do not conclude that the LLM played simply because model_requests increased.** Confirm the journal has `status=ok`.

## Structured output and unsuitable-model routing

On 11 October 2026, a live `openrouter/free` test chose `nvidia/nemotron-3.5-content-safety:free`, a moderation/safety classification model. It returned five text tokens, not a usable Surlife action. This was **not an AI strategy failure**. The earlier non-reasoning fix solved truncation but did not make random routing suitable for an experimental organism.

The gateway now pins **Qwen3.8 27B (free) by default**, a general instruction model with documented structured JSON support. Every request includes a strict `response_format: json_schema` describing the two action fields and `provider.require_parameters: true` so OpenRouter must route to an endpoint supporting structured outputs. No paid fallback is enabled. The referee still validates `mask` regardless of any provider-side promises, and known safety/embedding/reranking models are rejected as `unsuitable_model` if returned anyway. Unsupported endpoints may give `http_400` or another provider error rather than producing an action; Surlife will not silently retry.

**Reproducibility:** a pinned model removes one major source of random variation, but free providers, weights, inference settings and rate limits can still vary. For actual research, retain model/version, run ID, task seed and provider usage in the logs and repeat with controls. JSON schema support is a compatibility feature, not scientific validation.

## Scientific interpretation and next tasks

One prompt revision is **not** evidence of selection or improvement. The fake provider is a deterministic protocol test double, not a real LLM. Before claiming adaptation, run matched-seed static-soul versus mutable-soul versus random-revision controls, maintain held-out puzzle families, report actual requested/served models, unknown billing, model usage and all setup/trial costs, and explicitly separate direct correctness from energy survival. The Free Models Router is better for trying the system than for controlled comparative studies.

**Deferred:** paid models, provider-independent hard monetary billing caps, arbitrary tool use, Python code mutation/sandboxing (M2), GEPA integration, reproduction, multi-world scientific confidence analysis. This is a locally controlled M1 pilot; it never executes model-generated code.
