# Surlife M1.5 — Google Gemini free-tier API benchmark provider

M1.5 adds an **optional** Google Interactions API adapter for the M1.4
headroom/survival benchmark. Old M0–M1.4 OpenRouter and fake-provider
runs are untouched. Models can generate data-only masks, never executable
code or tool calls.

## Model and free-tier caution

Use **gemini-3.8-flash**, not the example's **gemini-3.7-flash**.
As of October 2026, Google's model documentation states that 3.7 Flash is
deprecated and automatically routed to 3.8 Flash. Google's Gemini API
pricing page lists free-tier tokens for 3.8 Flash, 3.5 Flash-Lite and
2.5 Flash-Lite. Surlife only allows these reviewed identifiers and rejects
aliases/unknown models.

**The key's billing tier cannot be verified by Surlife.** Confirm in
Google AI Studio that the specific API key/project is a Free Tier project.
The presence of a free-tier column does not prevent charges on a separately
enabled paid project. Free-tier prompts may be used to improve Google
products. Free rate limits vary by model, key/project and time.

Official docs:
- https://ai.google.dev/gemini-api/docs/models/gemini-3.7-flash
- https://ai.google.dev/gemini-api/docs/pricing
- https://ai.google.dev/gemini-api/docs/structured-output

## Install and first call (Fish)

```fish
cd ~/Documents/GitHub/surlife
git fetch origin
git switch --track origin/implementation/m15-gemini-provider-20261012
python -m pip install -e '.[gemini,test]'
pytest -q
```

Set your key **only in your private terminal**, not in GitHub, source
files or chat. To enter interactively without showing it on screen:

```fish
read -s -P 'Google Gemini API key: ' GOOGLE_API_KEY
set -gx GOOGLE_API_KEY $GOOGLE_API_KEY
```

Check the reviewed Gemini model name without any inference call:

```fish
surlife --provider google --check-model
```

It reports `free_tier_listed=true` and
`account_billing_verified=false` because Surlife cannot inspect your
Google project billing settings.

Make **one real call** in an entirely new report file:

```fish
surlife --m14 --provider google \
  --a llm --b greedy --cognition always \
  --max-requests 1 \
  --seed 17 --benchmark-cases 2 --benchmark-items 12 \
  --benchmark-profile mixed \
  --reasoning off \
  --benchmark-out out/m14-google-pilot.json
```

In Gemini, `--reasoning off` is approximated as
`thinking_level="low"` (Gemini 3.8 Flash does not support completely
disabling thinking). `--reasoning auto` selects medium.
No Google Search, tool calls, session chaining or automatic retries.
`store=False` requests stateless interactions.

If pilot succeeds, compare a longer series against existing baseline:

```fish
surlife --m14 --provider google \
  --a llm --b greedy --cognition selective \
  --max-requests 8 \
  --seed 17 --benchmark-cases 12 --benchmark-items 12 \
  --benchmark-profile mixed \
  --reasoning off \
  --benchmark-out out/m14-google-seed17.json
```

A successful API response does not guarantee a legal or optimal action.
Inspect `summary.arms.llm.model_actions`, `provider_failures`,
`energy_delta_vs_no_inference` and `failure_reasons`. No tokens are
fabricated when the provider omits usage. Each call costs one unit of
virtual organism energy, regardless of actual Google API pricing.

```fish
surlife --verify-benchmark-file out/m14-google-seed17.json
```

Old reports still replay through the same M1.4 mechanism.

## SDK and safety

The optional official `google-genai>=2.22.0,<3` package (Interactions
API plus Gemini 3.8 Flash support) uses:
- `genai.Client(api_key=os.environ["GOOGLE_API_KEY"], http_options={"api_version":"v1"})`
- `client.interactions.create(model="gemini-3.8-flash", ...)`
- bounded `generation_config.max_output_tokens` (maximum 1024 in Surlife)
- `response_format` with JSON schema for the selected mask
- Google-native `total_input_tokens` / `total_output_tokens` /
  `total_tokens` accounting, preserving missing counts as unknown.

Exception bodies, API keys and raw completions are not logged.
The referee independently validates the model-generated action.
HTTP 429 stops subsequent requests for the same benchmark and reverts
to the trusted Greedy fallback; there is no automatic retry.

**Scope limitation:** this PR enables Google only with `--m14`.
The earlier soul-evolution protocols need a separate provider-wide
integration and validation. This avoids expanding the attack surface and
breaking historical reproducibility in one step.
