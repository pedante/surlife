# Surlife M2.1 — First organism-owned prompt-mutation protocol

**Status:** offline, scripted-fake vertical slice (no genuine LLM learning).  
**Opt-in:** \`surlife --m21\`. Referee remains M0-v2; M2.0 ecology remains an optional separate arena.

## Purpose

The experiment tests whether an organism can **choose** when to spend scarce consultations to **propose**, **trial**, **activate or reject** a candidate change to its own versioned prompt. A persistent two-organism competition supplies objective rewards and upkeep. The central scientific goal is evolvable software, **not** soil/harvesting, physical terrain or an ecological simulation.

This stage is **engineering plumbing**. It does not yet connect real provider output, autonomous meta-reasoning, agent-written modules or economic selection across generations. The fake model deliberately understands one strategy phrase and can emulate an improvement. A successful promotion is not evidence of cognitive evolution.

## What is actually evolvable now?

- Separate \`Soul\` objects own base prompt, bounded experience notes, memories and version hashes.
- An initial, **scripted trusted metapolicy** chooses work, reflection/proposal, trial, activation decision, or model-assisted work according to previous losses and remaining request/energy budget. This is *organism-associated policy state*, **not yet an LLM choosing its own mutation plan**.
- A reflection fake consultation returns a candidate strategy note. The trusted runtime stages it with parent and candidate SHA-256 and **does not** append it to the active soul.
- Each holdout trial consumes one fake consultation (and one unit of virtual cognition energy). It compares the candidate behavior against a **cheap, unpriced Greedy baseline** on a separately seeded task. No model tokens are claimed.
- Following **three** trial results, a candidate is activated only with no score regression and at least one score-point total improvement. Activation changes the organism's prompt at a tick boundary; rejection preserves the original. The agent does not get to override the evaluator.
- A successful candidate can change later fake-provider work responses; fallback Greedy stays cheap. Strong unpriced optimal remains a reference and may make additional LLM spending pointless in practice.
- Every live tick uses the existing M0-v2 \`Arena\` for mint, upkeep, limited one-consultation-per-actor charge, independent work reward, optional duel, escrow and conserved virtual-energy accounting. A successful organism is **not** entitled to extra real provider calls.

## What the output records

\`manifest\`: pinned \`m21-v1\` rules, seed, identities/modes, request cap and trial count.  
\`episodes.primary\`: each tick's weather, task, scored actions, transfers, intent and before/after genome hashes; every candidate proposal/trial/outcome; synthetic model request type and prompt/response hashes; full final snapshot.  
\`episodes.frozen_control\`: a frozen/frozen matched-seed control with identical referee rules and no model calls.  
\`summary\`: virtual-energy difference from that control, fake request count, and **actual external requests/tokens of zero**.

Offline verifier independently regenerates the entire deterministic fake experiment from the manifest and compares all outcomes and digest. This catches tampering with action/mutation/ledger fields (a hash by itself does not prove authenticity). It does not perform new external consultations.

## Important limitations and next development step

1. **Fake model scripted to interpret a phrase.** No actual self-directed model reasoning, no hypothesis exploration beyond the one fixture, and no real cost-per-provider-token measurements.
2. **No independent live-model promoter.** Before real inference can be enabled, add versioned model consultation schemas, durable request/response capture or privacy-safe replay bank, calibration of paid evaluation versus true rewards, strict provider preflight spending limits and robust failure accounting. A fake improvement must never be promoted as a real-model improvement.
3. **Prompt improvement is not economic benefit.** The simple gate compares scores, while real research must compare **net survival/validated work after all training/evaluation calls, including failures, at matched total budgets**. Surlife's objective is capability per real token, not accumulated wealth alone.
4. **No code execution.** M2.2 requires a real isolated worker with hostile-code tests. This milestone neither imports nor runs organism-authored Python.
5. **No broad artificial world.** M2.0 remains optional. Priced environmental interventions ('weather') belong in a later bounded competition slice, not this one.
6. **M1.x and M2.0 backward compatibility:** existing CLI modes, report versions and journal logic remain unchanged.
