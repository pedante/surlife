# Surlife M1.1 — feedback-aware prompt evolution (experimental)

**M1.1 is opt-in.** M0/M1 and the deterministic referee remain unchanged.
The first eight-tick OpenRouter pilot, seed 11, yielded four invalid action masks,
no optimal decisions, 0 final energy and three auto-appended, puzzle-specific
notes. M1.1 addresses the observed issues without claiming to have solved
general learning or safely executing model-generated code.

## Run in Fish / CachyOS

```fish
cd ~/Documents/GitHub/surlife
git pull --ff-only
source .venv/bin/activate.fish
python -m pip install -e '.[test]'
pytest -q
```

Try an entirely offline M1.1 experiment first:

```fish
surlife --m11 --seed 11 --ticks 12 --a llm --b greedy --provider fake --cognition selective --max-requests 8
```

Then the provider model that has returned valid JSON in live M1 experiments:

```fish
surlife --check-model
surlife --m11 --seed 11 --ticks 12 --a llm --b greedy --provider openrouter --max-requests 8 --cognition selective --reasoning off
```

The actual returned `run_id` will be different; inspect the M1.1 soul:

```fish
cat out/souls/YOUR_RUN_ID/a.json
```

## Behavior

- A uses a **host-owned cognition schedule**, controlled by `--cognition selective`
  (default), `always`, or `never`. This is a **proxy for metacognition**, not an evolved
  neural/model policy. In selective mode, a model action is attempted at ticks
  divisible by three if energy is sufficient. Other action ticks use Greedy
  without an OpenRouter request.
- If a model action fails to achieve the optimum, a sufficiently solvent actor
  may spend its **next tick's single LLM consultation** reflecting on the actual
  referee feedback. During that reflection tick, trusted Greedy still submits
  a normal puzzle action. The reflection receives a separate JSON schema
  (`{"soul_update":"..."}`) rather than a bitmask-action schema. At most
  one consultation per organism per tick is charged, maintaining M0-v2
  accounting and replay.
- Every observation now records previous task inputs, selected mask/cost,
  capacity, legal/invalid outcome, optimum, regret, energy and action source.
  A task result with `score=-1` is an invalid selection; correctness
  (exact optimum) is tracked separately.
- Reflections can create a **pending** note. They must be short/general and
  cannot contain item-specific numbers. No untested note is inserted into
  `notes` or the active prompt. The maximum is one pending note at a time
  and three **accepted** notes overall.
- M1.1 currently implements model organism A versus scripted B only. M1
  supports its previous set of agent types and behavior unchanged.

## Evaluate before inheriting a new prompt

Evaluation is an **explicit operator action**, not something the organism
can silently launch. If the snapshot has one pending proposal:

```fish
surlife --evaluate-soul out/souls/YOUR_RUN_ID/a.json --provider fake --evaluation-seed 1009 --evaluation-tasks 4
```

Live evaluation with OpenRouter:

```fish
surlife --evaluate-soul out/souls/YOUR_RUN_ID/a.json --provider openrouter --evaluation-seed 1009 --evaluation-tasks 4 --eval-min-gain 2
```

**Budget:** 4 matched held-out tasks produce **8 real inference requests**
(4 each from old and candidate souls). These do not charge virtual arena
energy, do not modify the SQLite referee journal, and are capped to
`2 × evaluation_tasks`, but they still use the external provider's quota.
Use `--evaluation-tasks 2` for an initial 4-request pilot; 2–12 supported.

The evaluation uses identical unseen tasks and frozen memories, alternates
which prompt is called first, and records score, invalid choices, routed model,
reported tokens and failures. A note is *accepted* only if all provider
calls succeed, the candidate has no more invalid actions, and its total
reward score exceeds the baseline by at least `--eval-min-gain` (2 by default).
The decision, including rejection, is stored in the JSON snapshot. The
tested note enters the prompt **only on acceptance**.

You can continue lineage in a fresh experiment:

```fish
surlife --m11 --seed 17 --ticks 12 --a llm --b greedy --provider fake --inherit-soul-a out/souls/YOUR_RUN_ID/a.json
```

**Interpretation:** this small paired comparison is a provisional
acceptance rule, not proof of statistically significant general learning.
For stronger evidence, compare many independent evaluation seeds, enforce
no training/evaluation overlap and assess the real provider's nondeterminism.
The current holdout excludes exact tasks in the bounded feedback memory,
not every historical task the organism may have seen, so it is not a
research-grade data-contamination guarantee.

## Security and constraints

The model only returns JSON data. The host owns API keys, provider selection,
the strict JSON schemas, energy ledger and referee. No generated code is
executed; no privileged model tools exist. Prompt hashes detect accidental
changes, not malicious rewriting of both snapshot and hash. Reflections
and evaluations are explicitly bounded and provider responses are not
persisted verbatim. Live OpenRouter catalog checks fail closed before
inference. Never put API credentials into soul files.

The economy can still favor Greedy even against a perfect LLM: this is an
intended cost of cognition, but balancing harder tasks and evolving the
cognition scheduling policy remain future research.
